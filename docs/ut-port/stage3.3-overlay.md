# Stage 3.3: touch overlay

Goal (`stage3-roadmap.md`): the Android app's overlay, so games are playable without a controller. The user's condition for option A (3.0): the Android customization UX must be reimplemented.

3.3 is split in two, each with its own on-screen tests:
- **3.3a (this part, built):** the Android layouts for every controller type, in landscape and portrait, with the Android graphics, sizes, default positions and touch behavior.
- **3.3b (next):** the customization UX (edit mode, scale, opacity, show/hide controls, latching, reset) and its dialogs, drawn into the game picture (user decision for 3.4/3.3).

Status (2026-11-15): **3.3 done.** 3.3a and 3.3b passed their on-screen tests. One change after them: a latched L/R now also holds the analog trigger (re-test below).

## Findings and decisions

### Textures: ImGui user textures, freed with the on-screen UI

The overlay object outlives the video backend: it is destroyed after the game has stopped, when `g_gfx` is already gone. GPU textures it created itself would be freed too late. Instead, the images are registered as **ImGui user textures** (`ImGui::RegisterUserTexture`).
- Dolphin's own ImGui backend (`OnScreenUI::UpdateImguiTexture`) uploads them with the font atlas.
- It frees them when the on-screen UI is destroyed, before the backend shuts down.

ImGui 1.92 marks this API "experimental"; it is the cleanest fit, and if it changes, the textures move to an explicit creation and destruction around the backend's lifetime.

### A presenter draw area (VideoCommon, host side)

`Presenter::SetDrawArea(left, top, right, bottom)`, as fractions of the backbuffer.
- It defaults to the whole backbuffer, so nothing changes for other frontends.
- `UpdateDrawRectangle` fits the picture into that area instead of the whole window.

It is the only change outside `Source/Core/DolphinUT` in 3.3. It decides where the picture is drawn on the phone, not how the console behaves.

### Layout follows Android, including when the sideways layout is used

The sideways layout now appears only with the "Sideways Wii Remote" option on, as in the Android app. Its D-pad passes through unchanged, because Dolphin rotates it. A bare Wii Remote without that option gets the upright layout with the pointer. The user's profile has a Nunchuk, so Newer SMB shows the Nunchuk layout as in 3.0.

### Screen captures over adb

`mirscreencast` works from an adb shell with `ut-env.sh` sourced (it needs libhybris' TLS settings): `mirscreencast -m /run/user/32011/mir_socket -n 1 -f out.raw` gives a 1080x2400 RGBA frame of the whole screen, overlay included. This replaces asking the user for every look check.

While the phone is **locked**, Lomiri does not give the game window fullscreen (the greeter is active: `com.lomiri.LomiriGreeter.IsActive`). Captures then show the bottom 95 px of the shell under a 1080x2305 window. This is a test-condition artifact; the user confirmed fullscreen on screen in 3.2.

`run-dolphin.sh` accepts another user folder (`DOLPHIN_UT_USER=…`). A copy of the test config (`/home/phablet/dolphin-ut-user-t`) was used to see the upright, sideways and Classic layouts without touching the user's Wii Remote profile.

| Reset Overlay | The current layout's positions for the current orientation back to the defaults | removes the keys from `TouchOverlay.ini` |

How it is opened: a fourth button at the top centre, **"Controls"**, next to Exit, Save and Load. In the Android app the entry is in the in-game menu; it moves there in 3.4.

### How it works

- **Menu input.** While a menu page is open, its first finger becomes ImGui's mouse (`Presenter::SetMousePos` / `SetMousePress`, as DolphinQt's render widget uses), and the game controls get no touches. The ImGui calls are made after the overlay's own lock is released: the video thread holds ImGui's lock when it draws and then takes the overlay's, so taking them the other way round could deadlock.
- **Sizing for fingers.** About 4.5 % of the screen's shorter side per line of text (Dolphin already scales ImGui by 2.625). In landscape the main, pointer and long controller pages use two columns so that everything fits; ImGui cannot scroll by dragging, so the pages have no scrollbar.
- **Settings changes** run on the UI thread (posted from the video thread), are saved to `Dolphin.ini` at once, and then the overlay is rebuilt from the settings, as the Android app's `refreshInputOverlay`. Controls held at that moment, latched ones included, are released first.
- **Textures after a rebuild.** The new images become new ImGui user textures. The old ones are marked for destruction (`ImTextureStatus_WantDestroy`, `UnusedFrames = 1`), so Dolphin's ImGui backend frees them after the frame, and they then leave ImGui's list (`UnregisterUserTexture`). ImGui only counts unused frames for its own font textures, so the overlay sets it.
- **Positions** are saved as fractions of the window in `Config/TouchOverlay.ini`, `[Layout]`, under the Android app's keys: `<ButtonType>[_H|_O][-Portrait]-X/-Y` (the Android app keeps them in its SharedPreferences, in pixels). A saved position wins over the default; "Reset Overlay" removes them for the current layout and orientation.
- The controls are drawn on ImGui's background list: over the game picture, under the menu and Dolphin's own on-screen messages and statistics (3.3a drew them on the foreground list, above the menu).

### Latched L/R and the analog trigger

The Android app presses the analog trigger fully while the finger is on L or R, and lets it go when the finger lifts, **even when the button is latched** (`InputOverlay.onTouch`: 1.0 on down, 0.0 on up, whatever the latch). So a latched R keeps the digital R held but not the analog value, and games that read the analog trigger (Need for Speed's throttle) see nothing. The port copied that, and the user found it.

Changed: the analog trigger now follows the button's state (pressed or latched → 1.0, released → 0.0). For buttons that do not latch, this is exactly the Android behavior; only latched L/R differ, in the way a latched trigger is expected to work. This is the overlay's own logic, not an emulation change.

**Re-test (S3.3-M5b):** Latching Controls → L and R latching; in Need for Speed, one tap on R should keep full throttle until the next tap. Turn latching off again afterwards.
